# Offline-first architecture

1. Read `docs/architecture.md` before planning or editing data flow, synchronization, authentication, or storage behavior. Treat it as the source of truth.
2. Also read `docs/limitations.md` before planning or editing database connectivity, sync retries or batching, transaction budgets, or deployment topology.
3. Make the proposed change conform to every applicable constraint from the loaded documents. If the request conflicts with them, explain the conflict before editing.
