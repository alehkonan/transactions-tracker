# Project Structure (transactions-tracker)

This is a TanStack Start app. `src/` is organized by _role_, not by feature-type-per-folder.
This skill is the placement cheat sheet.

Path alias: `~/*` → `./src/*`. Always use it for intra-`src` imports (never relative `../../`).

## Where does a new file go?

| You're adding...                                       | Goes in...                                                                              |
| ------------------------------------------------------ | --------------------------------------------------------------------------------------- |
| A server function (`createServerFn`)                   | `src/api/<domain>.functions.ts` (kebab-case)                                            |
| A middleware (`createMiddleware`)                      | `src/api/<name>.middleware.ts` (kebab-case)                                             |
| A Drizzle table/enum                                   | `src/database/schema.ts` (single source of truth)                                       |
| A migration                                            | generated by `drizzle-kit` into `src/database/migrations/` — never hand-write           |
| The `getDb()` singleton                                | `src/database/get-db.server.ts` only — never elsewhere                                  |
| A server-only helper (not a server fn itself)          | `src/api/<name>.server.ts` (kebab-case, e.g. `selected-profile.server.ts`)              |
| A feature-specific component                           | `src/modules/<domain>/<ComponentName>.tsx` (e.g. `transactions/NecessityLevelTag.tsx`)  |
| A feature-specific `use*` hook                         | `src/modules/<domain>/<useHookName>.ts` (e.g. `transaction-form/useTransactionForm.ts`) |
| A feature-specific helper/type                         | `src/modules/<domain>/<kebab-name>.ts` (e.g. `accounts/account-type-tag.ts`)            |
| A shared, generic UI primitive (Button, Card, Dialog…) | `src/components/<ComponentName>.tsx` (PascalCase file name)                             |
| App chrome (Navbar, NotFoundPage, Loader)              | `src/components/` (chrome lives alongside primitives, not a separate `layout/`)         |
| A new route                                            | `src/routes/` (file-based; run `pnpm generate-routes` after)                            |
| A generic helper with no server/DB dependency          | `src/utils/` (e.g. `parse-csv.ts`)                                                      |

## Rules

1. **`src/api/` is the only place server functions live.** GET handlers read, POST handlers mutate. Every server function is composed with `.middleware([loggerMiddleware, authMiddleware])`, plus `profileMiddleware` on any function whose query needs to be scoped to the selected profile (it injects `context.profileId`, read from the cookie — see `profile.middleware.ts`; don't call `getSelectedProfileIdFromCookie()` directly from a domain handler, go through the middleware instead). Don't put `createServerFn` calls in `src/utils/`, inline in a route, or anywhere else — that's a stale pre-refactor pattern.
2. **Filenames are kebab-case everywhere in `src/`, with two exceptions: React components (PascalCase) and custom `use*` hooks (camelCase).** A component file is `<ComponentName>.tsx`; a hook file is named after the hook it exports (`useTransactionForm.ts`, `usePasskeyAuth.ts`, `useTransactionsImport.ts`). Everything else is kebab-case no matter what its exports are named — `format-money.ts` exports `formatMoney`, `read-cookie.ts` exports `readCookie`, `get-db.server.ts` exports `getDb`. Outside those two exceptions the file is named after the module, not the export, and the two do not have to match in case. Exempt because they are generated or framework-reserved: `routeTree.gen.ts`, `src/routes/__root.tsx`, `src/database/migrations/`. Route files under `src/routes/` are named after their URL segment (`transactions-import.tsx`), which is already kebab-case, and stay lowercase even though they export components.
3. **`src/database/get-db.server.ts` must have no top-level side effects.** The DB connection is created lazily inside `getDb()` so the TanStack Start compiler can tree-shake the postgres driver out of the client bundle. Never instantiate the client at module scope.
4. **`src/modules/<domain>/` groups by feature, not by file type.** A domain folder can mix components, hooks, and helpers for that feature (e.g. `modules/transactions-import/useTransactionsImport.ts` sits next to `modules/transactions/NecessityLevelTag.tsx`). Don't create a `src/features/` split-by-type layout — that directory was removed in favor of this.
5. **When a sub-feature outgrows its parent domain folder, promote it to its own sibling `src/modules/<name>/`.** `transaction-form/` (component + several single-purpose hooks: `useTransactionForm.ts`, `useAccountBalancePreview.ts`, `useTransferAmountMirror.ts`, `useTransactionFormSubmit.ts`, plus `transaction-form-values.ts`) was split out of `transactions/` this way once it grew past a couple of files — it's still consumed from `transactions/` (`EditTransactionButton.tsx`) and `routes/transactions.tsx` via `~/modules/transaction-form/...`, same as any other domain. Don't nest a growing sub-feature under its parent domain indefinitely (e.g. `transactions/transaction-form/`) once it has its own hooks/types/helpers worth grouping — a sibling module keeps import paths flat and signals it's its own unit, not a file-type split.
6. **`src/components/` is single-component-per-file, PascalCase filenames** (`<ComponentName>.tsx`), for things reusable across features or forming app chrome. If a component is only meaningful to one domain, it belongs under `src/modules/<domain>/` instead.
7. **Every React component, anywhere in `src/` (`src/components/` or `src/modules/<domain>/`), gets its own file: one component per file, named `<ComponentName>.tsx` in PascalCase.** This applies even to a small component split out of a larger one (e.g. `AccountForm` was pulled out of `CreateAccountButton.tsx` into its own `modules/accounts/AccountForm.tsx` once it stopped being a one-off). Don't stack a second component — even a small presentational one only used by the first — in the same file; give it its own file instead. Hooks/helpers that support a component are not components and don't get a PascalCase file — a `use*` hook is camelCase (`useTransactionForm.ts`), anything else is kebab-case. See rule 2.
8. **`src/utils/` has zero server or DB imports.** If a "util" imports `getDb`, `createServerFn`, or anything `.server.ts`, it belongs in `src/api/`, not here.
9. **`routeTree.gen.ts` is generated — never edit by hand.** Run `pnpm generate-routes` after adding/removing a route.
10. There is currently **no input-validation layer** wired into server functions (the old `src/utils/*.schema.ts` Zod schemas were removed). If you add validated mutations back, put the Zod schema next to the server function in `src/api/`, not in `src/utils/`.

## Red flags to call out during review

- A `createServerFn`/`createMiddleware` call outside `src/api/`.
- **A camelCase filename that isn't a `use*` hook** (`currencyRates.server.ts`, `formatMoney.ts`, `profileCookie.ts`) — rename to kebab-case. The exported name stays camelCase; only the file changes.
- A PascalCase filename that doesn't export a React component (e.g. a `Types.ts`) — PascalCase is reserved for components.
- A kebab-case filename for a `use*` hook (`use-transaction-form.ts`) — hook files match the hook name.
- A new `src/features/`, `src/layout/`, `src/pages/`, or `src/lib/` directory reappearing — these were folded into `api/`, `database/`, `modules/`, and `components/`.
- A component file that isn't PascalCase, or a file (anywhere in `src/`) that defines more than one component.
- A `getDb()` call, or postgres/drizzle client construction, at module scope instead of inside a handler.
- A relative `../../` import crossing into `src/` when `~/*` would work.
