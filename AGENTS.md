# Project: transactions-tracker

A **TanStack Start** (React 19) application for tracking financial transactions
across accounts. Full-stack SSR with a PostgreSQL database via Drizzle ORM.

> See `CLAUDE.md` for the fuller architecture/convention guide; this file mirrors
> the essentials and wires up the TanStack Intent skill loading above.

## Stack & integrations

- **Framework:** TanStack Start (React 19) — full-stack SSR, file-based routing.
- **Router:** TanStack Router (file router, `src/routes/`, generated `routeTree.gen.ts`).
- **Database:** Drizzle ORM + `postgres-js` (PostgreSQL). Schema in `src/drizzle/schema.ts`,
  migrations in `src/drizzle/migrations/`, config in `drizzle.config.ts`.
- **Validation:** Zod v4 schemas in `src/utils/*.schema.ts`, used to validate server-fn inputs.
- **Build/dev:** Vite 8 with `@tanstack/react-start/plugin/vite`, `@vitejs/plugin-react`.
- **Styling:** Tailwind CSS v4 via `@tailwindcss/vite` (+ `@tailwindcss/typography`),
  using semantic design tokens defined in `src/styles.css` (`@theme`).
- **Devtools:** TanStack Devtools + Router Devtools, wired via `@tanstack/devtools-vite`
  (stripped from production builds automatically).
- **Testing:** Vitest 4 + Testing Library + jsdom (no test files exist yet).
- **Lint/format:** oxlint + oxfmt (not ESLint/Prettier); Lefthook runs them on commit.
- **Language:** TypeScript 6. Path alias `~/*` → `./src/*` (see `tsconfig.json`).
- **Deploy:** Netlify (`netlify.toml`, `@netlify/vite-plugin-tanstack-start`).

## Scripts

```bash
pnpm dev              # vite dev on http://localhost:5454 (host exposed on LAN)
pnpm build            # production build (client + SSR) into dist/
pnpm preview          # preview the production build (port 5454)
pnpm test:unit        # vitest run
pnpm test:e2e         # playwright test
pnpm typecheck        # tsc --noEmit
pnpm lint             # oxlint  (lint:fix to autofix)
pnpm format           # oxfmt
pnpm generate-routes  # tsr generate (regenerate routeTree.gen.ts)
pnpm db:push-dev      # drizzle-kit push (sync schema to the dev DB)
```

## Project structure

- `src/router.tsx` — `getRouter()` factory + router type registration.
- `src/routes/` — file-based routes; `__root.tsx` is the SSR shell. `index.tsx` (dashboard),
  `transactions.tsx`, `statistics.tsx`.
- `src/routeTree.gen.ts` — **generated**, do not edit by hand (regenerated by `tsr generate`).
- `src/features/<feature>/` — self-contained feature UI (e.g. `add-transaction/`).
- `src/components/` — shared UI primitives (`Button`, `Card`, `Dialog`, `Title`, …).
- `src/layout/` — app chrome (`Body`, `Header`, `Navbar`).
- `src/pages/` — non-route page components (e.g. `NotFound`).
- `src/utils/` — server functions (`*.functions.ts`) and Zod schemas (`*.schema.ts`).
- `src/lib/db.server.ts` — lazy Drizzle singleton (`getDb()`); server-only, no top-level side effects.
- `src/drizzle/` — schema + generated migrations.
- `src/styles.css` — Tailwind entry + design tokens.

## Data flow

Route `loader` → server function (`createServerFn` in `src/utils/*.functions.ts`) → Drizzle
(`getDb()`) → PostgreSQL, rendered via SSR. There is no client-side data-fetching layer.
POST server fns validate input with a Zod schema via `.validator(...)`. Keep the Zod schemas
in `*.schema.ts` in sync with the Drizzle tables in `schema.ts` by hand.

## Conventions

- Single-component files are named `<ComponentName>.tsx` in PascalCase.
- Style with semantic token classes (`bg-accent`, `text-surface`, `border-border`), composed
  via `twMerge`/`twJoin` from `tailwind-merge` — not raw Tailwind colors.
- After adding a route, run `pnpm generate-routes` so `FileRouteTypes` paths type-check.

## Environment variables

- `DATABASE_URL` (PostgreSQL connection string) is required for the DB. `drizzle.config.ts`
  loads it from `.env.local`; server code reads `process.env.DATABASE_URL` at runtime.
- Only variables prefixed `VITE_` are exposed to client bundles; everything else is server-only.
- Use a local `.env` / `.env.local` (gitignored). Do not commit secrets.
